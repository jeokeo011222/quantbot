# QuantBot 自动升级方案

> 目标：为 QuantBot 桌面程序（Windows / Wails + Go）实现自动升级能力。升级包以**全量包**形式发布到公开 GitHub 仓库 `jeokeo011222/quantbot` 的 **Releases** 中，客户端自动检查、下载、校验并安全替换程序文件，且**绝不触碰用户数据**（config / database / log / 行情库）。

---

## 1. 总体架构

```
┌──────────────────────────── 客户端 QuantBot.exe ────────────────────────────┐
│                                                                             │
│  Wails 前端 (设置-关于)              Go 后端                                │
│  ┌──────────────────┐        ┌──────────────────────────────┐              │
│  │ 检查更新 按钮     │◄──────►│ App.CheckForUpdate           │              │
│  │ 版本/更新日志展示 │        │ App.DownloadUpdate(进度事件) │              │
│  │ 进度条           │◄──────►│ App.ApplyUpdate              │              │
│  │ 重启并升级 按钮   │        └──────────────┬───────────────┘              │
│  └──────────────────┘                       │                             │
│       ▲                                     ▼                             │
│       └──────── 事件通道 update:progress ◄──┤  internal/updater            │
└────────────────────────────────────────────┼──────────────────────────────┘
                                             │
                    ┌────────────────────────┴─────────────────────────┐
                    │  GitHub                                            │
                    │  api.github.com/repos/jeokeo011222/quantbot        │
                    │    /releases/latest   → 版本/更新日志/资源列表       │
                    │    /releases/assets/下载 → QuantBot-vX.Y.Z.zip     │
                    └────────────────────────────────────────────────────┘
```

- **检查**：调用 GitHub Releases API 获取最新版本（公开仓库免鉴权）。
- **下载**：下载全量包 zip 到本地临时目录，边下边校验 SHA256。
- **应用**：主程序以 `--apply-update` 参数拉起自身子进程后退出，子进程完成文件替换后重启新版（详见 §5 自我更新机制）。

## 2. 版本管理与发布格式

### 2.1 版本号统一（先决清理项）

当前存在三处版本号且不一致（`config.json` version=1.1.0、`SystemConfig.AppVersion`=1.0.0、`App.GetSystemInfo` 兜底 1.0.0）。方案要求收敛为**单一权威来源**：

- 新建 `internal/version/version.go`：

```go
package version

const (
    Version   = "1.1.0" // 语义化版本 major.minor.patch
    Channel   = "stable" // stable | beta
    BuildTime = ""       // 由构建脚本注入
)

// Compare 实现 semver 比较，返回 -1/0/1
func Compare(a, b string) (int, error)
```

- `GetSystemInfo` 的 `appVersion` 改为读 `version.Version`；`config.json` 的 `version` 字段仅作兼容保留。

### 2.2 GitHub 发布格式

每个版本发布一个 GitHub **Release**（tag 为 `vX.Y.Z`），包含两个附件：

| 附件 | 说明 |
| --- | --- |
| `QuantBot-vX.Y.Z.zip` | 全量升级包（仅程序文件，不含用户数据） |
| `QuantBot-vX.Y.Z.zip.sha256` | 升级包整体 SHA256 校验值 |

Release 的正文（body）即更新日志，客户端直接展示。

客户端通过 `GET https://api.github.com/repos/jeokeo011222/quantbot/releases/latest` 获取：

```json
{
  "tag_name": "v1.2.0",
  "published_at": "2026-08-27T10:00:00Z",
  "body": "## 更新内容\n- 新增自动升级\n- 修复...",
  "assets": [
    { "name": "QuantBot-v1.2.0.zip", "size": 75466752,
      "browser_download_url": "https://github.com/.../releases/download/v1.2.0/QuantBot-v1.2.0.zip" },
    { "name": "QuantBot-v1.2.0.zip.sha256", "browser_download_url": "..." }
  ]
}
```

> 仓库名/所有者、API 地址均做成配置项（`update_repo_owner`、`update_repo_name`），便于以后迁移或切换到私有/自建源。

## 3. 升级包内容（manifest.json）

zip 内包含 `manifest.json`，逐文件声明相对路径、大小、SHA256，**更新器只处理清单内列出的文件**。

```json
{
  "version": "1.2.0",
  "min_version": "1.0.0",
  "files": [
    { "path": "QuantBot.exe",             "size": 75466752, "sha256": "a1b2..." },
    { "path": "models/xgboost_astock_v1.json", "size": 12345, "sha256": "c3d4..." },
    { "path": "data/stock_dict.json",      "size": 1024,    "sha256": "e5f6..." }
  ]
}
```

### 文件分类策略

| 分类 | 包含 | 更新器动作 |
| --- | --- | --- |
| 程序文件 | `QuantBot.exe`、新增/变更的二进制 | **替换**（先备份） |
| 版本化数据 | `models/*`（XGBoost）、`data/stock_dict.json`（连带更新） | **替换**（先备份，允许回滚） |
| 用户数据（禁止触碰） | `config/`、`database/`、`log/`、`data/*.duckdb`、`data/trades/` | **绝不写入**，清单中禁止出现 |

> 说明：`tdx_sector_data.json` 已用 Go embed 打进 exe，无需出现在包内。**`data/stock_dict.json` 已确认连带更新**（属于版本化数据，走「备份→替换→可回滚」路径），由发布脚本固定包含；`data/` 下其余文件（duckdb 行情库、trades/）及 config/database/log 一律禁止进包。

## 4. 客户端更新流程（状态机）

```
         ┌─────────┐   点击检查/启动时   ┌───────────┐
         │  idle   │───────────────────►│  checking │
         └────┬────┘                    └─────┬─────┘
              │                               │
              │                               ├─ 无新版本 ─► idle（静默/轻提示）
              │                               ▼
              │                         有更新(展示日志)
              │                               │ 用户点「下载并安装」
              │                               ▼
              │                          ┌────────────┐   进度事件
              └──────────────────────────►│ downloading│──► update:progress
                                         └─────┬──────┘
                                               │ sha256 校验通过
                                               ▼
                                          ┌─────────┐   用户点「重启并升级」
                                          │  ready  │─────────────────────┐
                                          └─────────┘                     ▼
                                                              spawn --apply-update
                                                              主进程退出
                                                              子进程完成替换并重启
```

- **触发时机**：① 启动完成后异步检查一次；② 设置-关于页「检查更新」手动触发；③（可选）每 `update_interval_hours` 定时。
- **下载进度**：Go 侧用 io.TeeReader 统计已下载字节，经 Wails 事件 `update:progress` 推送 `{percent, downloaded, total}`。

## 5. 自我更新机制（Windows 关键点）

Windows 不允许**正在运行**的 exe 被删除/覆盖，但**允许重命名**。利用这一点实现「主程序自带更新器」，无需额外 exe：

```
1. 主程序已下载并解压到 build\bin\.update\<newVersion>\，逐文件核对 sha256 通过。
2. 主程序写 build\bin\.update\plan.json：
   { "new_version":"1.2.0", "parent_pid":1234, "stage":"...", "min_version":"1.0.0" }
3. 主程序以 --apply-update <plan.json> 拉起自身子进程，随后退出。
4. 子进程（运行同一 exe）：
   a. 等待 parent_pid 退出；
   b. 备份：QuantBot.exe → QuantBot.exe.old，models/ 等 → .update\backup\<relPath>；
   c. 复制 .update\<newVersion>\ 下的新文件到对应位置（此时旧 exe 已改名腾出路径）；
   d. 启动 QuantBot.exe（新版），子进程退出。
5. 新版首次启动成功（读取 plan.json 标记）后，清理 .update\ 与 QuantBot.exe.old。
```

### 失败回滚

- 任一步骤失败：子进程从 `.update\backup\` 还原旧文件，删除新文件，重启旧版，并把错误写入日志。
- 新版启动后若在 N 秒内异常退出（启动标记未清除），下次启动自动用 `QuantBot.exe.old` 回滚并提示。
- `plan.json` 同时携带 `single_instance` 豁免标记，子进程绕过单实例互斥检查。

## 6. 安全设计

| 风险 | 对策 |
| --- | --- |
| 传输被篡改 | HTTPS + zip 整体 sha256（Release 附件）逐字节校验；解压后按 manifest 逐文件 sha256 复验 |
| 来源可信度 | 公开仓库 + 固定 repo 地址；可选增强：发布者用私钥对 manifest 签名，客户端内置公钥验签（Ed25519），v1 先不做 |
| 部分下载/断网 | 下载到 `.part` 文件，校验不通过即删除重来，绝不应用不完整包 |
| 磁盘不足 | 解压前检查剩余空间 ≥ 包体积 ×2 |
| 杀软/SmartScreen | 未签名 exe 可能被拦截，文档提示用户「仍要运行」；后续可选代码签名证书 |
| 更新中用户数据被破坏 | 清单机制 + 「用户数据禁止触碰」白名单校验（manifest 中出现禁止路径直接拒绝） |

## 7. 后端模块与接口

```
internal/version/version.go   // 版本常量 + semver 比较
internal/updater/
    manifest.go               // Manifest 结构、解析、路径白名单校验
    github.go                 // GitHub Releases 客户端（latest + 资源解析）
    downloader.go             // 下载 + 进度回调 + sha256
    installer.go              // 解压、plan.json、备份/回滚、文件替换
    updater.go                // UpdateService 状态机
    apply.go                  // --apply-update 子进程入口（含等待父进程退出）
```

`App.go` 暴露给前端的 Wails 方法：

| 方法 | 说明 |
| --- | --- |
| `CheckForUpdate() → {has_update, current_version, latest_version, changelog, size, published_at}` | 检查是否有新版本 |
| `DownloadUpdate() → error` | 下载并校验（进度经 `update:progress` 事件推送） |
| `GetUpdateStatus() → {state, percent, downloaded, total, error}` | 前端拉取当前状态 |
| `ApplyUpdate() → error` | 写 plan.json、拉起 `--apply-update` 子进程并退出主程序 |

新增配置项（`config.json`，均有默认值）：

```json
{
  "auto_update": true,
  "update_channel": "stable",
  "update_interval_hours": 24,
  "update_repo_owner": "jeokeo011222",
  "update_repo_name": "quantbot"
}
```

## 9. 发布流程（发布脚本）

新增 `scripts/publish_update.ps1`（后端侧维护，不入前端开源仓库），或按下列步骤手动操作：

```powershell
# 1. 编译发布版
.\build.ps1            # 产出 build\bin\QuantBot.exe

# 2. 组装全量包（scripts/package_update.ps1）
#    收集程序文件 → dist\QuantBot-v1.2.0.zip + manifest.json + .sha256
#    （自动跳过 config/database/log/*.duckdb）

# 3. 发布到 GitHub（需已安装 gh CLI 并登录）
git tag v1.2.0
git push origin v1.2.0
gh release create v1.2.0 dist/QuantBot-v1.2.0.zip dist/QuantBot-v1.2.0.zip.sha256 --notes "更新日志..."
```

> GitHub `releases/latest` 按 tag 语义版本取最新（须保证 tag 按 semver 递增）。发布后用户端即可检查到更新。

## 10. 边界与注意事项

- **交易时段保护**：交易时段（9:15–15:05）默认不自动应用升级，只提示「已就绪，休市后重启升级」，用户可强制升级。
- **配置兼容**：升级后 `config.go` 对新增键自动补默认值（沿用现有合并逻辑），不覆盖用户已保存的值。
- **数据库迁移**：新版若变更 schema，沿用现有 sqlite.go 迁移模式在启动时执行。
- **单实例**：`--apply-update` 子进程带豁免标记，避免与主进程互斥。
- **更新包体积**：全量 exe 约 72MB，初始版本可接受；后续如需优化再评估增量/压缩（zstd）。
- **未签名提示**：Windows SmartScreen 可能提示「未知发布者」，需在 FAQ/免责声明中说明。
