E.2六个维度的数据源与降级链

「降级」是这套系统最诚实的部分：每一个维度都写明了「首选源拿不到时退到什么、再拿不到退到什么」。退到代理变量时，sources 字段里会留下原文——不写「已降级」，而是写清楚用什么代理的、代理值是多少。

E.3证据：同一维度的两版来源标注

下面的原文摘录来自运行库 market_sixdim_daily 的 sources 字段。把它按日期排开，你能直接看到这套系统「从代理走向真实源」的过程——这不是我的叙述，是库里的字。 2026-09-02（早期版本，多数维度在降级）：
  • breadth_rise：「全市场涨跌家数(涨0/总9533)=0%」
  • capital：「北向无实时源\(\to\)成交额连续放量天数代理=0；资金集中度=行业Top3成交额占比\(\ge\)40%(true)」
  • external：「无隔夜美股/事件实时源\(\to\)用上证指数开盘跳空代理(开盘缺口-0.16%(中性))」
  • sentiment：「采样300只日K(全市场统计不可用降级): 涨停0/跌停0/炸板率0%(日线代理)」
2026-09-09（改善后，多数维度已接真实源）：
  • breadth_rise：「代表样本涨跌家数(涨171/总300)=57%」
  • capital：「北向实时(同花顺hsgtApi): 当日净流入370亿\(\to\)连续流入口径5；资金集中度=行业Top3成交额占比\(\ge\)40%(true)」
  • external：「真实隔夜外围(tencent(qt.gtimg.cn) 全球指数实时:偏空)融合指数跳空(开盘缺口0.07%(中性))」
  • sentiment：「同花顺官方特色数据(实时): 涨停48/跌停7/炸板率36%(炸板27)」
两版放在一起，差别一眼可见：9 月 2 日那句「涨0/总9533 = 0%」是字典序抽样的产物——样本几乎全落在北交所，于是「上涨占比 0%」；9 月 9 日改成代表样本后，同样的市场读出的是 57%。指标没变，抽样变了，结论从「普跌」变成「普涨」。
降级到代理变量时，公式照跑，数字照出，看不出任何异常——9 月 2 日那天的广度就是 0%，程序不报错，界面也不闪红。这正是「代理变量必标注」这条纪律存在的理由：它不是给程序看的，是给人看的。你不去读 sources，就永远不知道这个 0% 到底是市场真的普跌，还是抽样抽歪了。 这也是本书引用数据时的一条硬规矩：凡是降级产生的数，一律标注它由什么代理而来；代理的覆盖率或样本量一并写出。系统里「样本 \(<100\) 标低可信度」「rt.covered == 0 告警」这两条，都是把这条纪律写进了代码。

动手试一试
  1. 读一次 sources。查 select trade_date, sources from market_sixdim_daily order by trade_date，逐条看六个维度是不是都标了来源；找出标注不全的那一天。
  2. 复算冲突修正。取 2026-09-10 那条：数一数六个分量里有多少个 \(\ge75\)、多少个 \(\le40\)。若冲突数 \(\ge2\)，用 raw_total_score\(\times0.8\) 看能不能得到 adjusted_total_score（38.43）。
  3. 看一次降级。在设置页把「六维判势」里情绪维度的首选源（同花顺官方）临时关掉，再跑一次盘前判势；对比 sources 里情绪那一格的文字，看它退到了哪一级。
