附录 I数据诚信原则与免责声明

这是全书最后一份「讲道理」的附录（它后面只剩一份用来查名字的索引），但如果你是完全不写代码、只想搞明白「这东西靠不靠谱」的读者，我建议你把它提到最前面读。原因很简单：一本书里的结论值不值得信，取决于它的数字是从哪来的、以及它在拿不到数字的时候怎么办。这两件事，比任何公式都更能决定这本书的成色。

I.1一、系统自己的态度：宁可不做，也不假装

这本书写的是一台正在运行的软件（QuantBot v1.6.0）。它在设计上有一条款项，贯穿了从启动到收盘的每一段流程，原文写得很直白：
数据不可用时必须报错，不得降级为默认值，不得使用虚假数据猜测。
这句话在工程上意味着几件具体的事，它们都不是口号，而是可以逐条去代码里核对的：
  • 启动时关键组件失败必须弹窗报错。 配置管理器、SQLite、股票时序库、投资组合引擎、大模型服务、智能体执行器——这六个组件里任何一个加载失败，程序会明确告诉你，并让你选择是否「仍然继续」，而不是自己悄悄降级成某种能跑但不完整的形态。
  • 所有实时数据源全部失败时，返回空，而不是返回伪造值。 行情源有优先级链（本地通达信、通达信 MCP、腾讯财经等），逐级回退；一路失败到底，结果就是空，而不是「上一次的数字」或「一个看起来合理的估计」。
  • 未配置密钥的付费数据源直接拒绝，不静默跳过。 同花顺官方数据服务需要 API Key，没配置就是明确的拒绝，不会伪装成「这个数据源本来就没有数据」。
  • 数据没更新到最新交易日，弹窗告警。 每天 16:00 拉取当日日线；如果发现库里最新日期落后于最后一个交易日，程序会提醒你，而不是拿旧数据算出一个新结论。
这四条合起来是一句判断：这个系统宁可停下来告诉你「我不知道」，也不愿意安静地给你一个错的答案。 本书引用数据时遵守的是同一条规矩。

I.2二、本书的三类标注

为了让读者随时知道「眼前这个数字是什么来路」，全书用三类醒目标注，出现在脚注里或表格下方：
标注含义与触发条件
真实数据该数字直接取自系统运行库，未做任何模拟、平滑或插值。全书出现 94 次。
复算数据该数字是本书按系统实现中的同一个公式、在系统的同一份真实数据上重新算出来的。用于那些系统界面没有直接显示、但可以由已有数据推导的指标。全书出现 7 次。
数据缺失该系统库中此项无有效记录。本书选择留白——表格里写一个「—」，而不是填一个看起来合理的估计值。全书出现 14 次。
此外，正文的每一处论断背后都有一条普通脚注，写清它对应的源码文件、代码行号或数据库表，并在末尾附上核对时间（本书的核对时间为 2026-09-24）。全书这样的脚注共 138 条，另有 83 处表格级来源说明。 一句话概括这套标注的用意：读者不应该需要相信作者。任何一个数字，你都应该能顺着标注找到它的出生地。

I.4四、系统里没有的东西

诚信的另一半，是承认自己没有什么。下面这些能力，在系统的历史版本里存在过，但在本书写作的版本中已经被移除或下线。本书全书不把它们写成现有功能：
  • 策略页的「策略诊断」（因子 IC 时序图）。 前端按钮与弹窗、后端绑定接口、相关源码文件全部删除。
  • 财务指标查询。 绑定接口与相关数据结构已删除。
  • 「查询前复权 K 线」入口。 前端输入框、查询按钮、结果表与后端方法均已删除。（前复权视图仍在，用于内部计算，但没有对外查询入口。）
  • 多因子回测。 已下线，回测仅支持单因子。
  • 通达信数据的自动执行。 已取消，改为仅手工补位。
  • 启动时自动刷新策略指标。 已取消，改为每日盘后调优写入或手动刷新。
  • 启动时自动重跑当日已完成的复盘与方案重建。 已取消，改为按复盘阶段定时执行，重启不重跑。
  • 估值快照与集合竞价快照（同花顺官方）。 相关方法、结构与解析逻辑全部删除。
如果你在别处读到「这个系统能做多因子回测」或「能查前复权 K 线」，请以这份清单为准。

I.5五、如实记录的两处系统缺陷

一本书如果只讲系统的优点，那它就不是在写工程，是在写广告。本书在写作过程中，通过对照源码与真实数据，发现了两处存在的缺陷。它们不影响本书的结论，但影响你对这套系统的信任边界，所以必须写出来。

I.5.1第一处：风险指标的历史法取数存在顺序缺陷

系统的行情查询函数 GetRecentPrices 按日期降序返回数据（最新的在前），而 CIO 模块里计算收益率的函数 computePositionReturns 拿到数据后没有重新排序，直接按相邻两点作差。对 \(121\) 根日线来说，这等价于把每一个收益率都做了符号翻转：
\[\hat r_i=\frac{c_i-c_{i-1}}{c_{i-1}}=\frac{-r_i}{1+r_i},\qquad r_i=\frac{p_i-p_{i-1}}{p_{i-1}} .\]
旁证很硬：同一个查询结果在另一个消费方（组合数据准备模块）里，是被显式升序重排之后才使用的——说明「需要重排」这件事在系统内部是有共识的，只是其中一条路径漏了。 在沪深 300 的真实数据上（2026-04-01 至 2026-09-23，\(121\) 根日线），这处缺陷造成的偏差是：
指标正确值系统输出偏差
VaR（95%）\(0.021441\)\(0.018362\)低估 \(14.4\%\)
CVaR（95%）\(0.028902\)\(0.024911\)低估 \(13.8\%\)
VaR（99%）\(0.030254\)\(0.029733\)低估 \(1.7\%\)
CVaR（99%）\(0.033147\)\(0.031724\)低估 \(4.3\%\)
最直接的验证是：系统返回的尾部第 7 个数是 \(-0.018362\)，把它反解回真实收益率是 \(+0.018031\)——那恰好是当期的第 7 大涨幅；而正确的分位数应当取第 7 大跌幅 \(-0.021441\)。 不受影响的量：日波动率（\(0.012723\) 对 \(0.012765\)，几乎不变，因为符号翻转不改变平方项）、相关系数（全体资产被同一个排列重排，配对关系不变，\(0.948144\) 对 \(0.948790\)）。受影响的量：年化夏普比率、最大回撤，以及所有基于收益序列方向的风险指标。影响范围限于三条调用路径；中台的风险计算与回撤熔断走的是另一条取数路径，不受影响。 本书的处理方式是：记账，但不改系统。附录 F 按理论正确口径给出全部推导，并在对照表里逐项标明这个差异。

I.5.2第二处：风险引擎把「数据缺失」和「风险为零」输出成同一个值

系统的风险引擎里，计算 VaR 与 CVaR 的函数在两种情况下都会直接返回 \(0\)：样本为空，或者传入的频度参数不在「日频 / 月频 / 年频」三者之中。 这意味着：「我没有数据」和「我的风险是零」在输出上无法区分。第 22 章讲过，风险为零是一个极强的结论——它意味着几乎不可能亏钱。而这里，它可能只是意味着「今天数据没接上」。 这不是计算错误，是接口设计问题：它把两种语义截然不同的情况压进了同一个返回值。正确的做法应当与系统自己的原则一致——数据不可用时明确报错，而不是返回一个 0 让下游当成事实。

I.6六、你自己怎么复现

上面每一个数字都可以由你自己复现。本书的导出与复算脚本都在 book/data/scripts/ 目录下：
  • export_real_data.py——只读连接行情库，把正文引用的真实数据导出为 JSON；
  • export_for_rest.py——第二批导出，供后半部章节与附录使用，口径与前者完全一致；
  • recompute_risk.py——复算附录 F 的全部风险指标数字，逐字照抄系统实现的取数与算法；
  • make_stubs.py——只用于生成章节骨架，不产出任何数字。
所有脚本一律以只读方式连接数据库（duckdb.connect(DB, read_only=True)），不会修改系统里的任何数据。运行环境需要 Python 3 与 duckdb 包。 验证的入口只有一条命令： 它会打印出第一节那张偏差对照表的每一行。如果打印出的数字与本书不一致，以你的运行结果为准——因为你的数据库可能就是更新过的，而本书的数字带着「2026-09-24」这个时间戳。
