第二十章今天能不能下注？（下）—— 数据从哪来，缺数怎么办

20.1一个“总是很淡”的市场广度

上一章末尾我留了一个尾巴：九月二日那条判势记录的市场广度，只有 181 分。 可我记得那几天盘面并不难看。涨停板上是有票的，只是系统说“上涨家数 0”。 我去查了这一天的 sources，广度的三个来源写得很清楚：
  • breadth_highlow：采样300只20日新高/新低(98/8)；
  • breadth_rise：全市场涨跌家数(涨0/总9533)=0%；
  • breadth_limit：采样涨停/跌停(0/0)。
“涨 0 / 总 9533”这行字，我当时读了三遍才反应过来：在 9533 只股票里，没有一只在上涨。这在任何一天都不可能发生，除非那天的行情库坏了。 行情库没坏。坏的是取样本的那一句 SQL。

20.2体检设备的精度说明

你去体检，拿到一台家用体温计，盒子上印着“精度 \(\pm 0.5\,^\circ\mathrm C\)”。 你不会因为这台机器不准就把它砸了。你会换一种用法：它测出 37.8，你不会据此判断“发烧了”，你会说“可能有点低烧，再用水银的确认一下”。 更关键的是：如果某天它显示 “--”，你知道那意味着没测出来，而不是“体温是零”。 数据源也是同一回事。每一个外部数据源都有它的精度、时效和失效方式；一个负责任的系统，要做的不是假装它们都一样准，而是把每一格的来源和可信度写在旁边。
这一章只回答一个问题：上一章那六个维度的分数，每一下是从哪儿取来的；取不到的时候，系统做什么。 答案有一条贯穿始终的底线。它写在这个包的源代码文件头上：
包级硬约束（原文，internal/marketsixdim/fetcher.go 文件头注释）
“数据来源原则（对应项目硬约束「严禁伪造数据」）：……缺失源用真实代理指标并标注……保证「严禁伪造数据」——任何无真实数据源的维度都明确标注为中性默认，不猜测。”
这句话拆成三条可执行的规则：
  1. 能取到真实值，就用真实值，并把来源写进 sources；
  2. 取不到真实值，可以退而用“代理指标”，但必须在 sources 里写明“这是代理”，并说清代理是什么；
  3. 连代理都没有，就给中性默认（50 分 / 0 / false），同样标注，绝不猜一个“看起来合理”的数。

20.3先讲最贵的那个错：抽样抽歪了

上面那条“涨 0 / 总 9533”，来自一个现在已经修掉、但值得单独立一章的错误。系统的真实事故清单把它列在第 #4 条：
真实事故 #4（摘录自系统事实清单）
症状：市场广度“总是很淡”，与盘面感觉不符。
根因：旧版 ORDER BY symbol LIMIT 300 字典序截断，样本几乎全落在北交所 + 沪 600。
修复：改分层代表样本 + 固定种子 20240901 可复现。
这个 bug 最值得讲的地方是：它不会报错。SQL 语法正确，返回 300 行，程序照常往下走。它只是安静地给你一个错的答案。 先把“错”写成可证明的东西。
定义 20.1（板块分层与真实占比）
设股票宇宙 \(\mathcal U\) 被划分为 \(B\) 个板块（沪主板、深主板、创业板、科创板、北交所），第 \(b\) 个板块含 \(N_b\) 只股票，\(N=\sum_b N_b\)。记真实占比
\[p_b=\frac{N_b}{N},\qquad \sum_{b=1}^{B}p_b=1 . \tag{20.1}\]
设第 \(b\) 个板块内“上涨股票”的比例为 \(\theta_b\in[0,1]\)，则全市场上涨比例为
\[\theta=\sum_{b=1}^{B}p_b\,\theta_b . \tag{20.2}\]
任一抽样方案给出板块构成的估计 \(\widehat p_b\)，其与真值的全变差距离为
\[d_{\mathrm{TV}}(\widehat p,p)=\frac12\sum_{b=1}^{B}\abs{\widehat p_b-p_b}\in[0,1]. \tag{20.3}\]
命题 20.2（字典序截断的偏差）
设符号列 symbol 的字典序把 B 个板块排成一个严格顺序，其中板块 \(b^\ast\) 的全部符号都小于其余所有板块的符号。令 \(n\) 为样本量，且 \(n\le N_{b^\ast}\)。则字典序截断 \((\code{ORDER BY symbol LIMIT }n)\) 得到的样本满足
\[\widehat p_{b^\ast}=1,\qquad \widehat p_b=0\ (b\ne b^\ast). \tag{20.4}\]
于是
  1. 全变差距离 \(d_{\mathrm{TV}}=1-p_{b^\ast}\)，即偏差完全由被过度代表的那一个板块决定；
  2. 样本上涨比例 \(\widehat\theta=\widehat\theta_{b^\ast}\)，其期望为
    \[\E[\widehat\theta]=\theta_{b^\ast}, \qquad \text{偏差}\quad \E[\widehat\theta]-\theta=\sum_{b\ne b^\ast}p_b\,(\theta_{b^\ast}-\theta_b); \tag{20.5}\]
  3. 偏差为零当且仅当所有板块的上涨比例相等（\(\theta_b\equiv\theta\)）。
这个命题在说什么：它把“抽样抽歪”从一句抱怨变成一条公式。第 (iii) 条最要紧——只要各板块表现不同（而它们永远不同），字典序截断就必然有偏，而且这个偏差和样本量 \(n\) 无关：你把 300 加到 3000，偏差一模一样，只是更自信地错。
证明■
(i) 由 \(n\le N_{b^\ast}\)，“最小的 \(n\) 个符号”全部落在板块 \(b^\ast\) 内，故 \(\widehat p_{b^\ast}=1\)，其余 \(\widehat p_b=0\)。于是
\[d_{\mathrm{TV}}=\frac12\Bigl(\abs{1-p_{b^\ast}}+\sum_{b\ne b^\ast}\abs{0-p_b}\Bigr) =\frac12\Bigl((1-p_{b^\ast})+(1-p_{b^\ast})\Bigr)=1-p_{b^\ast}.\]
(ii) 样本全在板块 \(b^\ast\) 内，故样本上涨比例只反映该板块：\(\widehat\theta=\widehat\theta_{b^\ast}\)。若板块内为简单随机抽样，则 \(\E[\widehat\theta_{b^\ast}]=\theta_{b^\ast}\)，于是 \(\E[\widehat\theta]=\theta_{b^\ast}\)。再用 \(\sum_b p_b=1\) 与 \(\theta=\sum_b p_b\theta_b\)：
\[\theta_{b^\ast}-\theta =\theta_{b^\ast}\sum_{b}p_b-\sum_{b}p_b\theta_b =\sum_{b}p_b\,(\theta_{b^\ast}-\theta_b) =\sum_{b\ne b^\ast}p_b\,(\theta_{b^\ast}-\theta_b),\]
因为 \(b=b^\ast\) 那一项为零。 (iii) 由式 (20.5)，偏差是 \(\{\theta_{b^\ast}-\theta_b\}_{b\ne b^\ast}\) 关于权重 \(p_b\) 的加权和。若所有 \(\theta_b\) 相等，每项为零，偏差为零；反之若存在 \(b\) 使 \(\theta_b\ne\theta_{b^\ast}\) 而 \(p_b>0\)，则该项非零，且因其余项不改变符号（在极端情形下全同号），加权和不为零。\(\blacksquare\)
用库里真实的样本量算一遍，就知道这个偏差有多大。stock_basic 里可交易个股的板块分布是：沪主板 17102、深主板 14973、创业板 14094、科创板 6175、北交所 3516，合计 55847。 若按字典序截断取 300 只，且“北交所”恰好排在字典序最前（\(b^\ast=\) 北交所，\(N_{b^\ast}=351\ge300\)），则： 修复方案也写在这个文件里。核心是三行代码： 这段话在说什么：三件事。第一，配额公式 \(q_b=\lfloor n\,N_b/N\rfloor\) 就是定义 20.1 里那个 \(p_b\) 的样本版本；第二，板内用固定种子打乱，所以同样的宇宙必然得到同样的样本——这叫可复现；第三，余量补足，保证样本量正好是 300。
命题 20.3（等比例配额的样本占比无偏）
设各板块按 \(n_b=\lfloor n N_b/N\rfloor\) 取配额，板块内为简单随机抽样（不放回），板块 \(b\) 内上涨比例 \(\theta_b\) 的估计为 \(\widehat\theta_b\)。记样本总量 \(n^\ast=\sum_b n_b\le n\)。则
  1. \(\displaystyle\sum_{b}\frac{n_b}{n^\ast}\widehat\theta_b\) 是 \(\theta\) 的无偏估计，当配额可整除（\(n_b=nN_b/N\)，\(\sum_b n_b=n\)）时；
  2. 板块占比估计 \(\widehat p_b=n_b/n\) 满足 \(\E[\widehat p_b]=p_b\)（整除时），\(d_{\mathrm{TV}}\to0\)（\(n\to\infty\)，整除）；
  3. 与命题 20.2 对比：字典序截断的偏差不随 \(n\) 减小，而等比例配额的偏差随 \(n\) 消失。
证明■
(i) 板块 \(b\) 内为简单随机抽样，故 \(\E[\widehat\theta_b]=\theta_b\)（样本比例是总体比例的无偏估计）。于是
\[\E\Bigl[\sum_b\frac{n_b}{n^\ast}\widehat\theta_b\Bigr] =\sum_b\frac{n_b}{n^\ast}\E[\widehat\theta_b] =\sum_b\frac{n_b}{n^\ast}\theta_b .\]
若配额整除，\(n_b=nN_b/N\)，则 \(n^\ast=\sum_b n N_b/N=n\)，且
\[\frac{n_b}{n^\ast}=\frac{nN_b/N}{n}=\frac{N_b}{N}=p_b ,\]
代入得 \(\sum_b p_b\theta_b=\theta\)，故无偏。 (ii) \(\widehat p_b=n_b/n\) 为常数（配额是确定性的），整除时 \(\widehat p_b=nN_b/(Nn)=N_b/N=p_b\)，于是 \(d_{\mathrm{TV}}=\frac12\sum_b\abs{p_b-p_b}=0\)。配额的取整误差 \(|n_b-nN_b/N|<1\)，故 \(\widehat p_b\to p_b\)，\(d_{\mathrm{TV}}\to0\)。 (iii) 命题 20.2 的偏差式 (20.5) 里没有 \(n\)：它只由各板块的 \(\theta_b\) 差异与 \(p_b\) 决定，加大样本量不改变它。而 (i) 的偏差恰为零，且 (ii) 的 \(d_{\mathrm{TV}}\le\frac{B}{2n}\to0\)。\(\blacksquare\)
这一节真正要记住的一句话
抽样偏差不会报错。SQL 会成功，数字会返回，曲线会画出来。
它只在你看不见的地方，把你的读数朝着某个方向推——推到你自己都相信“市场就是这么淡”为止。
所以任何“采样”都要能回答两个问题：样本的构成是什么？样本量是多少？

20.4第二个安静的错误：差一根 K 线

抽样偏差是“选错了对象”，还有一类错误是“数错了格子”。事故 #5 就是它。
真实事故 #5（摘录自系统事实清单）
症状：标注“20 日新高”，但实际只比对了 19 根。
根因：bars[len-20:] 把当前 bar 混入窗口。
修复：改为 bars[len-21 : len-1]。
命题 20.4（窗口混入当前 bar 的后果）
设第 \(t\) 日的收盘价为 \(c_t\)。按定义，第 \(t\) 日为“20 日新高”当且仅当
\[c_t\;>\;\max\{c_{t-20},c_{t-19},\dots,c_{t-1}\} \tag{$\star$}\]
即当前价高于此前 20 个交易日的最高收盘。设长度为 \(L\) 的数组 bars 以 bars[L-1] 为当前 bar。则
  1. 正确窗口为 bars[L-21 : L-1]，其下标集合是 \(\{L-21,\dots,L-2\}\)，恰好 \(20\) 个元素，对应 \(c_{t-20},\dots,c_{t-1}\)；
  2. 若误用 bars[L-20 : L]，其下标集合是 \(\{L-20,\dots,L-1\}\)，含当前 bar，对应 \(\{c_{t-19},\dots,c_t\}\)；
  3. 此时：若判定写 \(c_t\ge\max(\cdot)\)，条件退化为“\(c_t\) 不低于前 19 日”，即19 日新高，标签与口径不符；若判定写严格不等号 \(c_t>\max(\cdot)\)，则条件恒假，新高计数恒为 \(0\)（新低同理）。
这个命题在说什么：一根 K 线的错位，会让两个截然不同的结论同时发生——要么把“20 日新高”偷换成“19 日新高”，要么让它永远数不出一个。而两种情况在界面上都表现为“新高很少”，也就是事故清单里那句“市场广度总是很淡”。
证明■
(i) 数组下标从 \(0\) 计，总长 \(L\)，当前 bar 下标 \(L-1\)，对应 \(t\)。切片 bars[L-21:L-1] 含左端不含右端，下标集合为
\[\{L-21,\;L-20,\;\dots,\;L-2\},\]
元素个数为 \((L-2)-(L-21)+1=20\)。逐项对应：下标 \(L-21\) 即 \(t-20\)，……，下标 \(L-2\) 即 \(t-1\)。故恰为 \(\{c_{t-20},\dots,c_{t-1}\}\)，与 \((\star)\) 的窗口一致。 (ii) 切片 bars[L-20:L] 的下标集合为 \(\{L-20,\dots,L-1\}\)，元素数 \((L-1)-(L-20)+1=20\)，对应 \(\{c_{t-19},\dots,c_t\}\)，其中最后一项 \(c_t\) 就是当前 bar。 (iii) 记 \(M=\max\{c_{t-19},\dots,c_t\}\)。
  • 若判定为 \(c_t\ge M\)：因 \(c_t\) 是取最大值的候选之一，\(M\ge c_t\) 恒成立，故 \(c_t\ge M\iff c_t=M\iff c_t=\max\{c_{t-19},\dots,c_{t-1}\}\)（最后一步用了 \(c_t=M\) 时 \(M\) 由其余项决定）。即“不低于前 19 日的最高收盘”，是 19 日新高的定义，而非 20 日。
  • 若判定为 \(c_t>M\)：因 \(c_t\le M\) 恒成立，故 \(c_t>M\) 恒为假，计数恒为 \(0\)。新低同理（\(c_t<\min\{c_{t-19},\dots,c_t\}\) 恒假）。
\(\blacksquare\)
修复后的两个好处值得点出来：一是窗口正好 20 根，口径与标签一致；二是窗口严格落在当前 bar 之前，所以它在时间上只用了过去，没有偷看今天——这和第 第十七章 章讲的前视偏差是同一条纪律。

20.5六维的来源与降级链

现在把六个维度的真实来源摆出来。这张表是本章的核心，它回答的是“每个数从哪儿来”。 把这张表和第一章末尾那个真实的 sources 对照着读，会看出系统的“成长”： 这段话在说什么：九月二日的每一行几乎都带着“无实时源”“→代理”“降级”这样的字样，而且广度四成分的口径是混的——“采样 300 只”和“全市场”混在一起用，结果就是“涨 0/总 9533”这种自相矛盾的读数。九月九日之后，四个成分统一到同一个代表样本上（涨 171/总 300），情绪换成了同花顺官方实时池，资金结构拿到了北向实时净流入。

20.5.1缓存与限流：不是性能优化，是纪律

外部数据源（同花顺、东财、腾讯）都有一个共同特点：请求太密会被封。而盘中判势每 5 分钟跑一次，每次要覆盖约 300 只样本的最新价。 系统的处理写在 internal/marketsixdim/fetcher.go 里：一个包级的 ttlCache，实时快照的 TTL 设成 30 秒；外部源另有最小请求间隔限流。 这段话在说什么：三个动作。第一，加 TTL——30 秒内的重复请求直接吃缓存，既省请求也去抖。第二，非交易时段短路——收盘后“最新价”就是收盘价，库里有，不必去外部问一遍，这是事故 #18 的修复。第三，覆盖数为 0 时报出来——这是事故 #28 的修复；这一条最像本书反复讲的那个原则：降级可以是设计，但降级必须被看见。 还有一条口径标注规则：样本数小于 100 时，在 sources 里标“低可信度”。

20.6它在系统里长什么样

把本章的东西串起来，是四层：
  • 分层代表样本抽样、固定种子 20240901、等比例配额与余量补足：internal/data/duckdb.go 的 ListRepresentativeSymbols、repSampleSeed
  • 六维取数与降级链、TTL 缓存、非交易时段短路、覆盖数告警：internal/marketsixdim/fetcher.go 的 fetchSampleBars、aggregateSampleStats、realtimeSnapCache、ttlCache
  • 判势结果落库：internal/marketsixdim/persist.go 与 market_sixdim_daily
  • 五个维度的真实 sources 原文：market_sixdim_daily 的 sources 字段
  • 真实板块规模：stock_basic（沪主板 1710 / 深主板 1497 / 创业板 1409 / 科创板 617 / 北交所 351）
  • 相关事故：#4 字典序抽样落到北交所、#5 20 日新高 off-by-one、#18 六维延迟与限流、#28 覆盖数 0 无告警、#29 样本不足未提示
这是最危险的一句话，因为它的动机是“把活干完”。 本章里所有的兜底（北向没有就用融资余额、再没有就用成交额连续放量天数；外围没有就用指数跳空）看起来正像是“拿别的顶上”。它们和“编一个数”的区别在哪里？ 区别只有一个：代理指标是真实发生的另一个量，而且它的名字被写在旁边。 “北向连续流入 5 天”和“成交额连续放量 3 天”是两个不同的东西，后者不是前者。你可以在拿到前者之前先用后者做一次粗判断，但你必须知道自己在用后者——否则三个月后读这条记录的人（很可能是你自己）会以为那天真有北向数据。 系统把这条写进了包约束：“代理变量必标注”。而“数据缺失”这一类（order_book_daily 表当前 0 条记录，见第 第十二章 章）就老老实实留白，连代理都不编。
“我取 300 只不行，那我取 3000 只。” 看命题 20.2 的偏差式 (20.5)——里面没有 \(n\) 这个符号。字典序截断的偏差完全由“各板块的差异”决定，样本量再大也不减一分。你只是从“300 只全错”升级到了“3000 只全错”，而且更理直气壮。 这是抽样偏差最反直觉的地方：它随样本量增大而变得更自信，而不是更准确。无偏才是第一位的，样本量是第二位的。 系统里对应的一处细节值得抄笔记：样本数 \(<100\) 时标注低可信度。这句话在数学上什么都没保证，但它承认了一件事——可信度是一个需要被说出来的东西。宁可标注“这次样本少，请谨慎”，也不假装每一条记录同样可靠。
